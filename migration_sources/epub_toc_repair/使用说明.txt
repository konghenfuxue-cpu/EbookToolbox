EPUB 多卷合集目录修复工具
==========================
版本：2.4

用途
----
修复“多卷 EPUB 已合并，但阅读器目录只显示封面/开始，无法按卷和章节跳转”的情况。

适用结构
--------
工具支持两种常见结构：
1. 保留各卷 1/toc.ncx、2/toc.ncx……或 1/OEBPS/toc.ncx、2/OEBPS/toc.ncx……的合并合集。
2. 只剩一个主 OPF，但每卷仍保留 contents、contents0001……可视目录页的“扁平化合集”。
3. 只有一张总目录页列出多个卷名，每卷正文又拆成多个连续文件的合集。
4. 各卷源 toc.ncx 已经只剩封面/版权页，但主书脊仍保留 a1、a2……分卷标记的合集；此模式恢复卷级目录和可识别的后记。
5. 单卷 EPUB 3 的导航目标仍然存在，但目录链接文字全部为空；若另一张 p-toc/contents 页面保留“序章／一章／幕间／终章”等章名，工具会按顺序配对并恢复目录。

使用方法
--------
必须先右键 ZIP 选择“全部解压”，不能直接在压缩软件预览窗口中运行 CMD。

方法一：把一个或多个 EPUB 文件拖到“EPUB多卷合集目录修复.cmd”上。
方法二：双击 CMD，再把 EPUB 文件或文件夹拖进窗口，按回车。
方法三：拖入文件夹，工具会递归扫描其中的 EPUB。

输出规则
--------
原文件不会修改。
新文件保存在原目录，文件名增加“（已整理目录）”。
若同名输出已经存在，默认跳过，避免误覆盖。

处理内容
--------
1. 自动识别各卷与章节。
2. 优先提取书内已经存在的中文章节名；提取不到时保留日文标题。
3. 新增可在正文中打开的“合集目录”。
4. 同步重建 EPUB 2 的 toc.ncx 和 EPUB 3 的 nav.xhtml。
5. 检查压缩包完整性和所有章节锚点。
6. 支持没有 toc.ncx 的纯 EPUB 3，只重建 nav.xhtml 或 navigation-documents.xhtml。
7. 对“h1 里只有标题图片、没有文字”的章节，保留图片并补入不可见文字标题，使 Sigil/Calibre 的“从标题生成目录”可以显示章名。
8. 可继续处理已经由 v2.1 修复过导航的 EPUB，用于补充正文标题，不再误报识别失败。
9. 自动修复 manifest/item 被错误写入 XHTML 命名空间的问题，避免 Calibre 报“Book is empty, no content in spine”。
10. 输出前按 Calibre 的严格方式检查书脊，确认至少存在一个可解析的 XHTML 正文且文件真实存在。
11. 可修复 OPF 末尾遗漏 `</spine>` 导致的 XML 解析失败。
12. 可识别目录链接文件名已经失效、但 `#id001a` 等目标锚点仍存在于正文的 EPUB，并按锚点反查真实章节。
13. 对正文章名只是普通段落的书，在目标锚点处补隐藏 h1，供 Sigil/Calibre 生成目录使用，不改变阅读版式。

环境要求
--------
Windows 10/11；Python 3.9 或更高版本。
脚本不需要安装第三方模块。

常见失败提示
------------
“未识别到至少两卷”：该书不是本工具针对的合并结构，不能强行处理。
“无法确定第 X 卷对应的 OPF”：各卷原始清单已被删除或改名，需要单独分析。
“无效跳转”：正文中的章节锚点本身已经丢失，工具会停止输出，避免生成损坏文件。

命令行
------
python epub_collection_toc.py "D:\小说\某本合集.epub"
python epub_collection_toc.py "D:\小说文件夹"
python epub_collection_toc.py --overwrite "D:\小说\某本合集.epub"
